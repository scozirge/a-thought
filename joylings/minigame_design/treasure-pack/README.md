# 寶物背包

獨立本地 H5 原型，共 10 關。點選寶物放入或拿出背包；桌機也可拖進右側背包，或把背包內寶物拖回左側。重量不超過上限，金幣達到目標後按「帶走寶物」過關。

## 本地試玩
在此目錄執行 npm start，開啟 http://127.0.0.1:18126/ 。
伺服器只監聽本機。沒有外部素材或執行時套件依賴。

## 難度
- 1～2 關：3 件寶物，認識重量與金幣的取捨。
- 3～5 關：5～7 件寶物，開始比較組合。
- 6～8 關：8～10 件寶物，單件價值與整體價值不同。
- 9～10 關：12～14 件寶物，需要找出唯一的最佳組合。

每關目標都是該重量上限可達到的最高價值。第 3～10 關的最佳組合唯一。
第 5～10 關，以金幣由高到低、重量由低到高、金幣／重量由高到低依序選取，都無法得到最佳答案。
這些是關卡結構上的難度安排，實際適齡與完成時間仍需課堂試玩觀察。

不設倒數與操作次數限制。可以暫時超重，畫面顯示超重多少；提交時會提醒，保留選擇。
十關均可直接選取。切關與重新開始清空目前背包，保留通關勾記。
localStorage 使用獨立的 treasure-pack-v1，保存目前關卡、背包與完成關卡。退一步的歷史限本次頁面開啟期間。
手機以點選為主，重量、金幣與操作面板會隨捲動留在畫面上；桌機支援點選與拖曳。
數字寶物按鈕支援 Enter / Space，選取後維持鍵盤焦點。

## 驗證與輸出
- npm test：14 個測試，使用枚舉與動態規劃獨立檢查全部關卡最高價值、可解性、後段唯一解與貪心策略不足；驗證超重、目標、存檔、增刪。
- node tests/browser.cjs：使用隔離瀏覽器測試 10 關、滑鼠雙向拖曳、手機點選、鍵盤、重整、勾記、重來與 900／390／320px 排版。
- 瀏覽器測試需要 Playwright 與本機 Chrome。PLAYWRIGHT_PATH 可指定 Playwright 模組。
- npm run build：產生 dist/h5/ 四個靜態檔案，可供日後部署。

levels.json 是關卡資料備份，core.js 內含相同資料供免建置執行；測試會核對兩者一致。每個 items 元素為 [重量, 金幣]。
