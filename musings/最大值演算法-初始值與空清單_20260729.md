## 討論結果統整

題目中的程式將「最大值」初始化為 0，再逐一比較清單元素。這在清單含有正數時可能得到正確答案，但如果所有元素都是負數，0 會在沒有出現在輸入中的情況下被保留並回傳。

scozirge 正確判斷 `[3, 7, 2]` 會回傳 7，`[-5, -2, -8]` 會錯誤回傳 0。他也準確指出，問題來自把初始值設為 0，等於加入了「0 足夠小」這項未經保證的假設。修正方式可以把最大值初始化為清單第一個元素；若程式語言與數值類型允許，也可以使用負無限大。對空清單，scozirge 最後主張應回報錯誤警告，而不是把 0 當成答案。

| 輸入 | 原程式回傳 | 正確結果 | 問題 |
|---|---:|---:|---|
| `[3, 7, 2]` | 7 | 7 | 無 |
| `[-5, -2, -8]` | 0 | -2 | 0 不在輸入中，卻憑空成為答案 |
| `[]` | 0 | 沒有最大值 | 空清單沒有元素，0 不能代表最大值 |

較完整的修正版是：

```text
找最大值(數字清單):
    如果清單是空的:
        回報「空清單沒有最大值」

    最大值 = 清單中的第一個數字

    從第二個數字開始逐一檢查:
        如果數字 > 最大值:
            最大值 = 數字

    回傳最大值
```

這個版本的關鍵是：候選最大值一開始便確實來自輸入，之後也只會被另一個輸入元素取代，所以不會回傳清單中不存在的 0。

## 起始問題

一段虛擬碼想找出數字清單中的最大值，但先將最大值設為 0。題目要求追蹤正數與全負數兩種輸入、找出錯誤來源、提出修正方法，並決定空清單應如何處理。

## 重要前提

- 清單可能同時包含正數、0 與負數，不能預先假設至少有一個非負數。
- 最大值函式原則上應回傳清單中的某個實際元素。
- 空清單沒有任何元素，因此在未另外指定預設值的情況下，最大值沒有定義。
- 題目使用不依賴特定程式語言的虛擬碼，所以錯誤處理可以是拋出錯誤、回傳「沒有結果」的特殊值，或要求呼叫者提供預設值。

## scozirge 的解答

### 已正確掌握

- 正數清單 `[3, 7, 2]` 的輸出是 7。
- 全負數清單 `[-5, -2, -8]` 在原程式中會錯誤輸出 0。
- 初始值不能任意設為 0，因為這隱含假設 0 不會大於真正答案。
- 可以把初始值設為清單第一個元素，避免輸入之外的數值成為答案。
- 也可以考慮使用足夠小的特殊值；若使用負無限大，必須確認程式語言與資料類型支援。
- 原程式遇到空清單雖然會回傳 0，但正確設計應回報沒有最大值或提出錯誤警告。

### 需要補充的部分

「使用最小數字」需要先說明數值範圍。如果處理的是沒有固定下限的整數，就不存在一個可寫死的「最小整數」；如果使用固定寬度的整數類型，則可使用該類型的最小值，但仍可能降低程式對其他數值類型的通用性。因此，以第一個元素初始化通常是更自然且通用的做法。

空清單必須在讀取第一個元素以前先處理。合理選擇包括：

- 回報錯誤：「空清單沒有最大值」；
- 回傳 `null` 或其他代表「沒有結果」的特殊值；
- 由函式介面要求呼叫者提供空清單時的預設值。

選擇哪一種取決於程式的使用情境，但不能在沒有說明的情況下直接把 0 當成數學上的最大值。

## 共識與結論

- 初始化不是單純的格式選擇，而是演算法正確性的一部分。
- 初始候選值若不來自輸入，就可能在不符合條件時憑空成為答案。
- 以第一個元素初始化，可以正確處理全部都是負數的非空清單。
- 空清單沒有最大值，必須在存取第一個元素以前另外處理。
- 對空清單回報錯誤、回傳特殊值或要求預設值都是可能設計；應由函式契約清楚說明。
